# Spec: story-drag-dismiss —— 故事页跟手拖动返回（仿 App Store）

- **ID**: 218-story-drag-dismiss
- **状态**: in-progress
- **日期**: 2026-10-16
- **来源**: 用户提供的真机录屏 `ScreenRecording_10-16-2026 18-53-25_1.MP4`（4 秒，
  iPhone，App Store Today 里点开故事后拖动返回），按 6fps 抽帧逐帧对照。
- **接续**: specs/217-app-store-clone（Today 卡片展开已做，收起只有 ✕）。

## 1. 要解决什么

217 的展开故事只能点右上角 ✕ 收起。真实 App Store 里还有一条**跟手的拖动返回**，
是这个页面最有"原生感"的交互，而我们完全没有：

录屏里观察到的行为（抽帧）：

1. 故事页停在顶部时，手指往下拖，**整页（封面 + 正文 + ✕）作为一个整体跟手**：
   位置跟着手指的 x/y 走，同时等比缩小（拖到约 0.8 倍时仍在跟手）。
2. 缩小过程中**圆角从 0 变大**（拖到 0.8 倍时约 25–30px），页面边缘露出底下的
   Today 页。
3. 露出的背景**变暗/变灰**（Today 页被压暗），越拖越暗。
4. 松手：已拖过一段距离 → **从当前姿态飞回原卡片位置**，同时圆角收回到卡片的 20px，
   背景恢复，tab 栏淡入；没拖够 → 弹回全屏。
5. 全程**没有**露出 tab 栏（展开期间被盖住），松手落回后才出现。

## 2. 不做什么（Non-goals）

- 不做左边缘右滑返回这一条（路由级的 `fjs-slide` 手势只管 push 出的页面，故事层
  是同页 overlay，不在路由栈里）。只做"从顶部下拖"。
- 不做背景真实模糊（`backdrop-filter` App 端没有）；用黑色半透明遮罩近似变暗。
- 不改运行时：不新增标签 / 事件 / prop，不动 `packages/`。
- 不做 Android 返回键 / 预测式返回的联动（overlay 宿主已把展开层判为 modal 拦截
  返回键，行为沿用 217）。
- Web 真触摸设备上浏览器会接管竖向 pan（`pointercancel`），拖动在移动浏览器里
  不保证；桌面鼠标 / DevTools 触摸模拟可用。登记为已知差异。

## 3. 用户可见的行为

故事页（`CardExpand.vue`）已展开且 `contentOn` 之后：

- **触发**：手指在故事页内容区按下时，滚动偏移为 0（页面在顶部）→ 进入"待判定"。
  向下移动超过 10px 且纵向位移大于横向 → 进入拖动；向上移动超过 6px → 放弃本次
  手势，交还给滚动。页面不在顶部时从不触发（照常滚动）。
- **拖动中**（每个 touchmove 一次样式更新）：
  - 姿态：`transform: translate(dx, dy) scale(s)`，`dx/dy` 是手指相对拖动起点的位移；
  - 进度 `p = clamp(max(dy,0) / (视口高 × 0.4), 0, 1)`；
  - `s = 1 - 0.3 × p`；圆角 `r = 28 × p`（px，写在姿态容器上，视觉圆角约 `r × s`）；
  - 背景遮罩不透明度 `0.4 × p`；
  - ✕ 随页面一起缩放；拖动期间页面里的点击不触发。
- **松手**：
  - `dy > 视口高 × 0.15` **或** 松手瞬时下滑速度 > 0.7 px/ms → 收起：内容淡出（120ms），
    然后从**当前姿态**的矩形用 240ms 飞回原卡片位置（原卡片仍挂载，重新测距），
    圆角 → 20px，遮罩淡出；
  - 否则 → 回弹：姿态用 300ms `cubic-bezier(0.32,0.72,0,1)` 回到全屏，遮罩淡出。
- `touchcancel` 一律按"回弹"处理。
- ✕ 按钮的收起路径不变（217），拖动返回是第二条路径，两条互不干扰。

## 4. 两端约定（宪法 I）

| | Flutter | Web |
|---|---|---|
| 触摸事件 | `onTouchstart/move/end/cancel`，一根手指按在哪个节点后续 move/end 就归它（App 上是原始指针事件，与滚动手势竞技场无关） | pointer 事件 + `setPointerCapture`，桌面鼠标可拖 |
| 姿态 | `transform` 的 translate + scale（只重绘），圆角是逐帧直接写的 `border-radius`（不走 transition） | 同 |
| 回弹 | `transform` 的 transition | 同 |
| 载荷 | `clientX/clientY/timeStamp`，逻辑像素 | 同 |
| 已知差异 | — | 移动浏览器真触摸时竖向 pan 被浏览器接管，会 `pointercancel`（回弹） |

## 6. 验收标准

1. `pnpm --filter app-store-clone run typecheck` 通过；`pnpm run typecheck`、`pnpm test` 不变红。
2. Web（`dev:web`，桌面鼠标）：展开 Today 故事 → 页面在顶部时向下拖：整页跟手、缩小、
   圆角变大、背景变暗；松手拖得够 → 飞回卡片；拖得不够 → 回弹全屏。
3. 页面已向下滚动（不在顶部）时向下拖是正常滚动，不触发拖动返回。
4. iOS 模拟器（`fjs run ios`）：同第 2、3 条，行为与 Web 一致。
5. 拖动返回收起后，卡片完整恢复、再次点开仍正常（没有残留 modal 层，217 T052 的坑）。
6. ✕ 仍然可以收起；快速连点不会让状态卡在中间。
7. 代码里不出现 `gc()`；不新增依赖；`packages/` 零改动。
