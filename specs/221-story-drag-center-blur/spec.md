# Spec: story-drag-center-blur —— 拖动返回锁定中心、缩到阈值自动返回、背景高斯模糊

- **ID**: 221-story-drag-center-blur
- **状态**: in-progress
- **日期**: 2026-10-16
- **来源**: 用户第二段真机录屏 `ScreenRecording_10-16-2026 19-47-42_1.MP4`（5.3 秒，按 8fps 抽帧），
  接续 specs/218（拖动返回）。

## 1. 要解决什么

218 的拖动返回和真实 App Store 还有两处不一样（抽帧逐帧对照）：

1. **页面不该随手乱跑**。录屏里拖动时整页始终**水平居中**、不跟着手指位移，只是以屏幕中心为原点
   **等比缩小**（缩小的同时圆角变大）；缩到一个阈值（约 0.85 倍）时**不等松手**，直接飞回卡片。
   218 做成了「跟手位移 + 缩放 + 松手判距离/速度」。
2. **背景是高斯模糊 + 压暗，不是单纯变暗**。露出的 Today 页被模糊（卡片、标题都糊成色块），
   越缩越糊；飞回卡片时随之清晰。218 只做了黑色半透明遮罩。

## 2. 不做什么（Non-goals）

- 不借 `@ufjs/liquidglass`：背景模糊用 CSS `filter: blur()`，它是独立的运行时能力，由
  specs/222-css-filter-blur 补齐（Flutter 渲染 + lint + 文档），本 spec 只是它的第一个使用方。
- 不做松手后的惯性延续：在阈值前松手，速度够快就收起，否则回弹（与 218 同）。
- 背景模糊不要求两端像素一致（见 css-compat 玻璃节：blur / tint / radius 一致，折射不保证）。

## 3. 用户可见的行为

故事页到顶后手指下拉：

- **锁定中心**：页面不做 translate，只以屏幕中心为原点 `scale(s)`；手指水平移动不影响页面。
- **缩放进度**：`p = clamp(max(dy,0) / (视口高 × 0.4), 0, 1)`，`s = 1 - 0.3 × p`；圆角 `28 × p`。
- **阈值自动返回**：`s` 降到 `0.85`（对应拉动 `0.2 × 视口高`）时立即收起：内容淡出、从当前缩放姿态
  飞回原卡片，手指还按着也不再响应。
- **松手**：阈值前松手，下滑速度 > 0.7 px/ms 收起，否则回弹全屏（回弹时模糊退到 0）。
- **背景**：拖动一开始，被盖住的 Today 页面自己 `filter: blur(20 × p px)`，同时在故事页下面叠一层黑色
  （透明度 `0.35 × p`）。收起飞行 / 回弹期间两者线性退到 0（`filter` 在 App 端不插值，所以由 JS 逐步写）。
  页面内容放在独立容器里被模糊，`CardExpand` 在容器之外（Web 上 `filter` 会让元素成为其
  `position: fixed` 后代的包含块）。

## 4. 两端约定（宪法 I）

| | Flutter | Web |
|---|---|---|
| 缩放 | `transform: scale()`，只重绘 | 同 |
| 背景模糊 | `filter: blur(Npx)` → `ImageFiltered`（specs/222），逐帧写 | 浏览器原生 `filter: blur()` |
| 已知差异 | 逐帧改 `filter` 是否平滑、大半径的耗时要模拟器验 | — |

## 5. 契约变更（宪法 II）

- [x] 都不涉及（只用既有 `glass-surface` 标签与 style）

## 6. 验收标准

0. 依赖 specs/222（`filter: blur()` 两端可用）。
1. `pnpm --filter app-store-clone run typecheck`、`pnpm run typecheck`、`pnpm test` 通过。
2. Web：到顶下拉——页面始终水平居中、只缩放、圆角变大；背景有模糊；缩到 0.85 自动飞回；
   阈值前慢速松手回弹；离开顶部时下拉不触发。
3. iOS 模拟器：同第 2 条；`filter: blur` 逐帧变化不报错、不闪；飞回后背景清晰、卡片完整、宿主里无残留。
4. 不改 `packages/`；无 `gc()`；无新依赖。

## 7. 待澄清

无。阈值与系数取自录屏估计，手感可后续只改常量。
