# Spec: 注册新作用域的样式表不再清空样式缓存

- **ID**: 120-scoped-register-keeps-cache
- **状态**: done
- **日期**: 2026-09-24

## 1. 要解决什么

用户真机实测（2026-09-24）：`fjs run ios`（debug，dev server 单包）vant 页 `[nav] mounted`
17–51 ms，`fjs run ios --profile`（分包 + 字节码）反而 59–81 ms。

分包模式下，页面 chunk 在打开时才执行，执行时注册它自己的 scoped 样式表；
`StyleEngine.register()` 每次都 `matchEpoch++`、清空 `matchCache`（连同 specs/076 的
retired 保留）并把**所有存活元素**标脏。于是：

- 之前页面攒下的 vant 组件匹配 / 计算缓存全部作废，每个新页面都从全冷开始；
- 垫在下面的页面（首页、tab 页）整页重算一遍。

离线复现（容器口径，vant-form，前面挂过 vant-basic、vant-more）：

| | 同步段 | CSS | match miss |
|---|---:|---:|---:|
| 挂载前不注册（dev 单包的情形） | 44–47 ms | 28–31 | 86 |
| 挂载前注册一张新作用域的表（分包的情形） | 65–73 ms | 49–56 | 234 |

一张 scoped 表的规则只命中**带这个作用域**的元素（`:deep` 时是自身或祖先带）。
注册时如果还没有任何元素（或缓存条目）用过这个作用域，它不可能改变任何已有答案。

## 2. 不做什么（Non-goals）

- 不改全局（非 scoped）样式表的失效策略：它可能命中任何元素，照旧整体失效。
- 不做「按作用域精确失效」（作用域已被用过时只清相关条目）：dev 热更新重复注册才会
  走到，收益小、正确性风险大，照旧整体失效。
- 不改匹配 / 级联语义。

## 3. 用户可见的行为

页面代码零改动。分包构建（`--pages`、`fjs run --profile/--release`）下，打开新页面
不再清掉其他页面的样式缓存，也不再重算垫在下面的页面。

## 4. 两端约定（宪法 I）

| | Flutter | Web |
|---|---|---|
| 行为 | 注册新作用域的表不清缓存；结果与清缓存时相同 | 不涉及（浏览器 CSS） |

## 5. 契约变更（宪法 II）

- [x] 都不涉及

## 6. 验收标准

1. `pnpm run typecheck`、`pnpm test` 通过；新增单测：
   - 新作用域的 scoped 表：注册后缓存条目保留、已挂元素不标脏；
     之后挂载带该作用域的元素，样式与「注册即整体失效」的引擎逐元素相同（含 `:deep`）；
   - 走整体失效的情形：作用域已被元素用过；表里有 `:root` 或
     `@keyframes`；注册改变了 media / structural / sibling / pseudo 开关；全局表。
2. 离线复现（上表的场景）：注册一张新作用域的表后，vant-form 挂载的 match miss 与
   不注册时相同，同步段差距 ≤ 5%。
3. 不注册 scoped 表时的 op 流与改前逐字节相同；注册时逐节点解析后的样式与结构相同。
4. 真机复核交用户（`fjs run ios --profile`）。
